# 故障排查

在成员窗口登录后，点「返回群聊并检查连接」。TWOS 会核对该群绑定的会话；网页确认附件超时时，原草稿可在同一会话核对。显示就绪后，点「继续排队的消息」。登录时可以查看其他历史对话，团队任务仍使用自己的会话。

送达情况待确认时，点「核对原会话」。输入框里已有的个人草稿会保留。TWOS 按原交接记录核对送达和对应回复。较长的工程指令可以用带校验摘要的 UTF-8 附件传递。长消息接近上限时，TWOS 会引用已经包含的相同正文，保留独有证据和冻结文件。以后更改成员设置，只影响后续任务。 部分文件更新后，如果审核者要求核实旧版交付文件，可以点击「核对交付文件并发给审核者」。TWOS 会回读本群交付的文件，把相对路径、内容摘要及来源版本交给审核者。目录中的其他个人文件保持私有。

Ada 可以接着第一轮继续对话。使用网页当前选择的成员会跟随网页。若成员固定了型号，群聊会列出设定值和网页实际选择。可在网页切回设定型号，或在群聊采用网页当前选择，作用于后续轮次。

双栏里的两个自动发送复选框控制同一次接力。如果 Claude 项目有两个输入框，TWOS 需要确定选中的讨论串。若仍无法识别，可单独打开目标讨论串后继续。从 ChatGPT 访客会话开始接力前，请先登录。

群聊首条消息停住时，点**核对原会话**。TWOS 会到对应成员的会话核对这一条消息。确认为待发草稿时，可点**发送已核对的草稿**发送一次。网页已确认送达时，TWOS 会在页面切换期间继续查找对应回复。

本机制作任务确已超时中断时，可点**沿用规划重新制作**，这会发起一次新的模型调用。若原轮次已完成，点**恢复文件并继续审核**会使用已有结果。审核要求修改时，团队可能自动开始下一次制作并使用提供方额度。

### 第一条消息待发时如何继续

群聊暂停时，提示会点明成员和服务。点**刷新连接**即可检查该成员的窗口。若提示登录，请在该窗口完成登录，再点**返回群聊并检查连接**。看到**连接已就绪**后，点**继续待发消息**即可，无需重新输入。刷新本身不会发送消息。若旧版本连续排入了相同消息，选**继续一次，跳过重复消息**会保留历史，只派发一次。只有确实想分别执行时才选**保留并继续全部**。已有派发回执但送达状态不明的消息，只能核对原操作。

### 应用被移动或由 macOS 转置运行

只读连接绑定准确的签名生产端，也核对应用路径。移动／替换 TWOS，或 macOS 将带隔离标记的副本放到另一临时路径运行后，独立 Nyra 可能显示 NOT_CONNECTED，而显示／隐藏仍可用。将核验过的应用安装到“应用程序”后打开；如需恢复关联，在 **夜璃状态 → 连接** 明确续接只读状态。不要删除偏好或关闭 Gatekeeper。此前 R3 隔离安装检查中，macOS 转置路径变化正确地使旧关联失效；此情况不宣称自动重连通过。

### 旧回执身份提示

“找到内容相同的旧回执，消息身份需核验”表示旧回执使用了会随历史重载变化的位置序号。仅正文相同不足以确认新一轮身份。TWOS 保留旧回执并阻止重复发送，不再提供另一个 Send 或宣称新消息已送达。“更多 → 交接记录”可以只读核验。需要继续时正常产生新回复，不要为了消除提示重放旧任务。新版备用标识绑定当前回复及其前置用户消息，加载更多历史不会重新编号。

## 本轮状态／返回排障
