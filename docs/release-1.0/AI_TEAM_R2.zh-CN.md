# TWOS 1.0.16 AI Team 使用指南

AI Team 会在每轮发送前核对成员网页当前的选择。旧群若把 Medium 等思考强度保存成型号，可以继续使用网页当前选择。若明确设定的型号与网页不同，群聊会列出两者。可以采用网页显示的选择，再继续待发消息。重新打开成员窗口时会定位到本群最近一次确认的会话。

Claude 项目同时打开讨论串时，双栏自动发送只使用已识别的讨论串输入框和消息区。左右两个复选框控制同一次接力。项目草稿和其他讨论串的回复独立保留。若无法识别目标，可单独打开要接力的会话，再点「继续自动发送」。

### 第一条消息待发时如何继续

群聊暂停时，提示会点明成员和服务。点**刷新连接**即可检查该成员的窗口。若提示登录，请在该窗口完成登录，再点**返回群聊并检查连接**。看到**连接已就绪**后，点**继续待发消息**即可，无需重新输入。刷新本身不会发送消息。若旧版本连续排入了相同消息，选**继续一次，跳过重复消息**会保留历史，只派发一次。只有确实想分别执行时才选**保留并继续全部**。已有派发回执但送达状态不明的消息，只能核对原操作。


在工作台顶部点 **AI Team**，再点群聊列表里的 **新建任务**。直接说明想得到什么。例如，让团队解释一段话，或将一份会议纪要整理为清单。文字任务可以在聊天里完成。需要文件时，从 **成果文件** 选择已有目录，里面可以有自己的文档。

## 在一个群聊中工作

- 创建群聊时，协调者继承左侧当时可读取的配置。打开 **成员** 可以更改姓名、提供方、可用模型、强度和职责。网页成员可先点 **打开连接**，在官方网页选好型号，再点 **采用网页当前选择**。变更从后续分派开始生效。输入框的语言选项设置本群任务的输出语言。
- 默认三位成员，最多再加三位。一人可以兼任多项职责。独立审核需要不同的制作人、审核人，以及不同模型的调用证据。执行详情会分别列出请求模型和提供方回报的模型。
- 普通消息发给协调者，用 **@** 可以指定一人或多人。通过 **＋** 选文件，也可以拖入文件或粘贴图片。群聊记录收件人、提交时的附件版本及派发回执。通道无法读取某个附件时会显示具体问题。
- 执行中，符合条件的补充可以送入本机 Codex 的指定活动轮次。发给其他成员、或不支持实时追加的通道时，消息进入对应队列。点成员消息旁的执行状态查看过程。**停止** 仅作用于当前群聊，其他群聊有自己的队列。
- 任务进行中可切换群聊或新建任务。草稿留在原群。重启后如有一条送达待确认的消息，回到原群点 **核对状态**，核对已有派发后再继续。
- 完成后可直接追问原因，也可提出具体修改来开启后续工作。主动停止后，需要明确提出继续制作。旧群聊可以在原群继续，**载入旧版群聊** 可载入早期预览记录。历史私人备注仅在本地显示。

## 查看与验收成果

打开 **成果文件** 可看到选定目录和真实文件，并可 **预览**、用系统应用 **打开** 或 **在 Finder 中显示**。成果直接位于所选目录或项目正常需要的子目录，冻结审核版本由应用保管。遇到外部编辑或另一群聊的同名文件，会显示冲突。核对原件后，可另选合适的目录保存当前成果。

审核针对冻结的内容。阻断项需要对应需求、位置、证据和修复建议。仍有实际进展时可继续第三次及以后的修订。调整策略后同一缺陷仍然存在时，会在群聊提出需要你决定的问题。接受操作针对已核对的版本。提供方缺少逐次真实型号时，执行详情记录缺口，独立审核的正式通过状态保持待确认。

## 从 GitHub 下载后验收

1. 安装对应 GitHub Release 的 DMG。打开 AI Team，新建一个文字任务。
2. 附加一份非敏感说明，@ 两名成员，提一个需要阅读说明才能回答的问题。将两人的答复与原文对照。
3. 重开原群继续追问。如需文件，选择现有成果目录，用「在 Finder 中显示」核对。明确要求修改成果后，在同一个群里查看新版本。

## 恢复网页草稿

群聊显示「草稿 · 尚未发送」时，点 **核对原会话**。原稿一致时可点 **发送已核对的草稿**。如果已在成员网页手动发送，回到群聊再核对一次即可读取回执。如果输入框为空，先查看成员窗口，确认从未发送后再点 **确认未发送，恢复草稿**。恢复只会填回原文，点击发送才会派发。

成员已收到消息时，群聊会等待网页打开对应会话并取回回复。本机文件制作超时后，已完成的规划会保留。核实原调用确已中断后，点**沿用规划重新制作**，可在同一个群聊中发起一次新的制作调用，使用现有 Codex 套餐额度。

即使提供方没有返回模型型号，群聊也会交付已完成的制作结果。若旧版本在超时边界保存了完成回执，点**恢复文件并继续审核**即可核对原调用、结果哈希并派发审核。生成的根目录 Git 忽略规则以可见的 **gitignore.example** 交付。

旧派发显示 **送达待确认** 时，可打开原成员窗口，再点 **核对原会话**。TWOS 会先查找对应的已发送消息，再显示草稿核对结果。此操作保留现有草稿和原派发记录。

## 继续原群任务

登录后点击 **返回群聊并检查连接**。成员窗口空闲时，TWOS 会回到本群已绑定的会话。新群从新对话开始。如果窗口里有草稿、附件或正在生成的回复，请先在原窗口保留或完成这些工作。网页仅显示默认型号时，可以选择 **后续轮次使用网页默认选择**，用于此后的任务。

要核对旧消息，点 **核对原会话**。TWOS 会打开记录的地址，找到对应的用户消息，并在可用时展开折叠的正文核对。如果旧规划仍然无法核实，群里已经有另一条不同的指令，可以点 **保留原请求为未确认，核对下一条指令**。确认就绪后点 **继续待发消息**。旧记录和审核意见保留在群里。

发给 ChatGPT 或 Claude 的长篇团队指令未附带其他文件时，TWOS 会把指令作为 UTF-8 文件上传，随附一条含 SHA-256 的简短说明。上传前核对原始字节，收到回复时核对同一条用户消息中的说明和文件。明确未发送的旧草稿，可在核实原输入框为空并选择恢复后使用这个格式。

本机制作超过 30 分钟时，TWOS 会检查同一提交、线程和轮次的近期活动。持续执行的任务最长可运行 90 分钟，已保存的制作结果可以从原回执恢复。

## 安装与回退

从 [GitHub v1.0.16](https://github.com/loseyourself1978-blip/tianma-work-os/releases/tag/v1.0.16) 下载安装包，打开前核对 SHA256SUMS。升级前请先结束正在执行的任务并正常退出 TWOS。要回退，请正常退出 1.0.16，从 [v1.0.15](https://github.com/loseyourself1978-blip/tianma-work-os/releases/tag/v1.0.15) 获取上一版；保留原群聊配置和成果目录。
