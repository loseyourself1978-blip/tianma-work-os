TWOS hosts official provider websites and a local Codex App Server client. Each provider applies its own account, retention, plan and usage terms. TWOS does not merge all visible services into one quota pool or silently switch billing paths. No credits, resets or subscriptions are purchased automatically.

Only explicitly selected handoff text/attachments should be sent to the bound destination. Choosing a folder does not authorize reading all its contents. Local execution is restricted to the confirmed scope, with real approval requests retained. HTML artifacts open outside the product's authenticated page/native bridge.

The Nyra status channel receives bounded read-only state and opaque correlation identifiers, never chat bodies, source code, accounts, credentials or business ledgers. The pending control-enabled build uses a separate authenticated channel for a user-clicked focus, draft edit, supplement or exact-task stop. That channel necessarily carries the selected draft/supplement to TWOS and then through the task’s existing authorized provider route. Nyra cannot independently execute, approve, trade, select a new recipient or expand file permissions. Signature and peer checks remain in place. Local preferences are separate from application code. Published diagnostics must remove private content.

The pet does not require Accessibility, full-disk, microphone, screen-recording or global keyboard permissions for ordinary local animation. A directory prompt may occur when the user selects a protected folder. Screenshots/recordings are separate user-authorized actions. No startup login item is silently created.

Nyra’s task editor additionally keeps at most one local `task-input-recovery.json` in its application state directory before transmitting a draft/control operation. It contains only the explicitly entered text, a bounded task title/provider and opaque target identity; no attachments or credentials. The file is owner-only (0600), its directory is 0700, and a matching acknowledged save/delivery clears it. Retained recovery is displayed copy-only after reopening; it is never automatically sent. Discard requires an explicit local confirmation.

The authenticated control channel also returns up to two bound task summaries: provider, side, a title of at most 90 characters, state/freshness, available actions and opaque correlation IDs. A summary may retain an ended or stale task for result inspection or draft recovery. It does not return raw workspace paths, accounts, complete conversations or attachment contents.
