# R4 verification scope

STATIC means source/boundary inspection; SIMULATED means explicitly synthetic pages/events in real WebKit; REAL_GUI means dedicated ChatGPT/Claude conversations and native controls; OWNER_CONFIRMED preserves earlier limited Nyra/debate acceptance. These evidence classes are not interchangeable.

R4 engineering records cover one checkbox driving both sides for at least three real round trips, both native stops, host Stop, enabling while generating, adoption of a manual in-flight handoff, explicit text-file upload/content reading, and Nyra sizing/frame advancement. The release receipt identifies the exact candidate, final complete-gate counts, coverage and limits; historical R3 totals are not an R4 gate.

Observed races and deterministic simulated races are recorded separately. Unobserved mouse/timing behavior is not claimed as real. Stop cannot recall in-flight content; uncertain delivery stays unknown until read-only reconciliation. Implementation PASS requires the matching stable-input complete green gate. New UI Owner acceptance is separate and pending.

Restart-specific finding: provider history hydration changed the position-based fallback message ID. An already-sent reply regained a Send action; no duplicate was executed. The repair uses a public message ID where available, otherwise a SHA-256 anchor of only the selected reply and its preceding user message. Legacy position-only receipts with matching content are treated as ambiguous and block replay; they are not rewritten or presented as proof that a new message was sent. Focused and final packaged verification are recorded separately.

Stopped-session recovery: an unresolved receipt from a stopped loop no longer globally blocks a different, explicitly selected complete reply. TWOS first inspects the old delivery when its target is still open, preserves that receipt and its uncertainty, then applies the same per-message deduplication and target preflight to the new selection. Selecting an already consumed reply waits for new content; it never resends the old turn. Paused active exchanges retain their original bound scope.

Final packaged GUI also exposed a launcher-language propagation gap: changing the saved language updated the launcher but left the open paired panes in the prior language. The launcher now refreshes the existing workbench after a successful preference save and when an externally changed preference is observed. A real Cocoa/WebKit fixture verifies visible labels, persistence, unchanged routing and zero handoff/model dispatch; final packaged GUI verification remains separately recorded.
