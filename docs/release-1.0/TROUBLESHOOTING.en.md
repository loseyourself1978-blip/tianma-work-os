### App moved or macOS translocated it

The read-only link is bound to the exact signed producer, including its application path. Moving/replacing TWOS, or macOS running a quarantined copy from a different temporary path, can leave standalone Nyra at NOT_CONNECTED while Show/Hide still works. Install the verified app in Applications, open that version, then use **Nyra status → Connect** to explicitly renew the read-only association if needed. Do not delete preferences or disable Gatekeeper. In the earlier R3 isolated installer check, a changed macOS translocation path correctly invalidated the old link; that case is not claimed as automatic reconnection.

### Older receipt identity

“Matching older receipt found; message identity needs verification” means an old receipt used a rendered position that can change when history reloads. A matching body alone does not identify a new turn. TWOS preserves the receipt and blocks a duplicate instead of offering another Send or claiming the new turn was delivered. **More → Handoff history** inspects without resending. Continue with a genuinely new reply when needed; do not replay an old task to clear the notice. New fallback identities bind the selected reply and its preceding user message, so loading older history does not renumber them.

## Current status / return troubleshooting

The bubble shows observed replying, execution, queueing or waiting-for-action work, then closes on confirmed idle or terminal state. An observation gap is briefly unconfirmed, never an indefinitely running old task. If an old engineering Nyra occupies the singleton, quit it through its own menu and use Show Nyra in the intended TWOS. Do not delete profiles or force-stop other apps. Character return needs no edit grant; unavailable edit/Stop actions require checking the exact task and current permission. Choose tiny-voca F2 for English; Chinese Tian is unchanged and sound still starts muted.
