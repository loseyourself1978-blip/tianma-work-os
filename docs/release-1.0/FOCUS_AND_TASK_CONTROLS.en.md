# Nyra focus, task controls and the shared Codex workspace

Candidate: TWOS 1.0.10 / 101.58 and Nyra 1.0.7 / 107. Work order: TWOS-NYRA-FOCUS-AND-TASK-CONTROLS-R1. **Development change: final packaged GUI verification and release are still pending.** This document does not change the current public download or grant Owner acceptance.

## Upgrade check

Use the matching verified release once it is published. Existing accepted business tasks do not need to be recreated.

1. Select Codex in either pane. The same project/chat sidebar, conversation stream and composer are used on either side. Choose a chat in the sidebar; the chat dropdown is removed. The sidebar can collapse in a narrow pane. Model, reasoning and input-mode selectors keep their existing purposes.
2. The official connection supplies project and chat metadata. Where app project membership is not exposed, a folder-based grouping is labelled as such. This is a TWOS client of the official protocol, not an embedded copy of the whole Codex application. Reading history does not transfer control of an official application's active run.
3. Recent public conversation items are read in bounded pages and deduplicated by item ID. Saved turn summaries alone are insufficient for a currently active official chat. Older history remains on demand. A stale/read failure keeps the previous content and shows its status; it never silently resumes a turn. Only public progress summaries are shown, not hidden reasoning.
4. With Nyra connected, click the visible character once to restore the exact bound TWOS workbench. Dragging moves the character instead. A task-title click selects the bound side; a changed target is rejected. A receipt is confirmed only after the host is active and its workbench window is visible, unminimized and key.
5. Current task cards use a compact translucent two-line bubble. Long titles are truncated, with the full title available on hover. The pencil and Stop controls are directly available; no expansion is needed to enter text. The chevron only reveals the selector when both sides have tasks. The bubble shows side/provider, the available conversation title and real state. Missing titles use an explicit placeholder. Stale observations retain the last card with actions disabled. Show/hide current tasks remains a persistent preference; hiding it does not stop work.
6. Click the **Edit input** pencil once. A compact translucent composer opens with keyboard focus; it locks its target, preserves the composer draft and supports IME composition. Enter sends, Shift+Enter inserts a new line, and Escape or the close icon closes without sending. Standard Cut, Copy, Paste and Select All keyboard shortcuts use the focused native text editor. Normal drafts save automatically; there is no separate Save-draft step. For a TWOS-controlled Codex turn, choose the supported **Steer** or **Send after the current task completes**. Web providers only offer the latter. Selecting or editing a draft does not send it. Existing attachments must be reviewed in TWOS, not silently attached by Nyra.
7. Select a pending input to edit only its unsent text. Enter or the arrow saves that queued revision; closing discards the unsaved revision and leaves the original queue item unchanged. Queued edits are not autosaved. A sent instruction is never overwritten. A changed task, directory, draft revision or host retains your input and refuses redirection. Closing the editor preserves the target; when the host is available, a normal composer draft is saved through TWOS, while cancelling an unsent queue edit leaves its original item unchanged.
8. **Stop** first cancels the matching future dispatch/automatic relay, then interrupts only the exact active task. **Stopping** is not **Stopped**. An acknowledgment alone is not a terminal result. An uncertain stop remains explicit; it never rolls back files or affects unrelated tasks. A late response cannot restart the stopped queue.

End this upgrade check here. First-use and continuing-task instructions remain separate; do not rerun an accepted travel page or debate.

## Permissions and privacy

The existing status socket remains read-only. The separate authenticated user-control socket supports only inspect, focus, draft, submit, editQueue and stop. Both peers verify user, live process, exact application/signature, instance, request freshness and opaque task identity. The embedded component is pinned inside the signed TWOS application; standalone controls require an explicit TWOS authorization through **Nyra status → Enable Nyra task controls…**. Existing status-only grants do not silently gain controls.

Status snapshots do not contain prompts, code, files, accounts or credentials. The user-control channel necessarily carries the particular draft and supplement that the user chooses to edit/send, up to 64,000 UTF-8 bytes. TWOS stores these in its existing local draft/queue/receipt system and passes them only through the original authorized provider pipeline. No automatic approval, shell command, file access, arbitrary recipient or expanded directory permission is granted to Nyra. Metadata diagnostics omit titles and instruction bodies. Showing the card can reveal a bounded conversation title on screen; hide task labels before screen sharing if desired.

All I/O and signature verification are off the UI thread. A four-second bounded request lease is revoked on timeout or connection reset; delayed authentication cannot send a new action afterward. Mutating request IDs are deduplicated for the host lifetime. Reopening or reconnecting never replays an uncertain operation. After an explicit send, a bounded read-only check observes that same task’s receipt; it does not send again. Closing during autosave keeps the frozen editor until the save is confirmed. An unconfirmed send retains its text and disables resubmission.

## Troubleshooting

- **Unconfirmed send/edit:** resend is disabled. Keep the editor open and inspect the original receipt in TWOS. Before an edit or send crosses the control channel, Nyra saves one bounded local recovery record (maximum 64,000 UTF-8 bytes, owner-only file). A matching confirmed save or delivery removes it; stale acknowledgments cannot remove a newer record. After a rejected/unconfirmed send, or after reopening, any retained recovery text is copy-only and cannot be sent or written to a new task automatically. Review its original task in TWOS. “Use TWOS draft” asks before discarding recovery and loading the current draft. This is local recovery storage, not another queue. Uncommitted IME text and keystrokes before autosave are not claimed crash-durable.
- **Connection/state needs verification:** the task remains bound and input is retained. Wait for TWOS to reconcile the same run, inspect its receipt, then use the explicit recovery action. A temporary connection gap does not revoke the original authorization and is not reported as a different controller owning the task. No send is retried automatically.
- **Task changed / draft retained:** return to the displayed task in TWOS and explicitly choose the correct target. No supplement is redirected.
- **Read-only or unavailable:** the official app still owns that run, the standalone control grant is absent, the selected host is old, or current state is not exposed. Read/history access is distinct from execution control. Use TWOS's existing connection/permission entry; do not delete credentials.
- **Stop unconfirmed:** inspect that exact task's current state. Do not repeatedly send Stop to a different task or kill the official application.
- **Window focus not confirmed:** the peer was not observed as the active visible workbench; open the bound TWOS instance normally and inspect its connection. The application is not launched by an arbitrary path or display name.
- **Latest chat appears stale:** check the read-only update timestamp and refresh. Bounded item reads do not require thread/resume and do not send a model task.

macOS only. Windows is in development and has no downloadable build. Existing five outfits, audio and accepted business outcomes are unchanged.

The task selector keeps the same conversation when a new turn starts. Login/landing pages without an observed run do not become task cards. After an owned execution ends, the editor can still save its draft, but does not silently start another turn.
