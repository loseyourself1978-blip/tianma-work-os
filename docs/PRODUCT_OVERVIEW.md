# TWOS 1.0 · 产品介绍

TWOS 把讨论和执行放在同一个 macOS 窗口中。你在 ChatGPT 整理目标，确认完整指令与目录后交给本机 Codex；工作过程在右侧持续显示，完成结果回到原讨论，形成下一轮迭代的上下文。

已有目录、语言、附件、用量与运行观测保持。正常纯文本网页交接采用一次点击，绑定实际目标、正文及回执，不自动循环对话。ChatGPT → Claude 的接收与运行、Show Nyra 和日常换装已有 Owner 接受记录。

本轮 TWOS 1.0.1 候选内置 Nyra 1.0.0：新用户只安装 TWOS 即可显示夜璃，无需另装 Pets 或从开发目录取素材。独立 Nyra 同时交付。两者只读消费任务状态与关联标识，不接收聊天、代码或凭据，也没有执行和批准权限。通道结束、核验结果和 Owner 接受分别记录。三套服装支持站姿和侧卧；透明舞台、悬停、方向拖动及手动试播的正式状态以联合发行验证记录为准。

## 适合的工作

制作本地网页、整理可执行开发需求、检查与修改明确授权的源码，以及围绕实际成果继续讨论。生成网页默认保留在本机，公开发布是另外的操作与授权。

## 日常流程

| 你做什么 | TWOS 做什么 |
| --- | --- |
| 在官网讨论需求 | 保留原 ChatGPT 账号、模型与聊天 |
| 确认任务目录 | 将规范目录、权限范围与真实 Codex 会话绑定 |
| 点击交付指令 | 发送完整正文、明确附件及控制端核验上下文 |
| 执行时补充需求 | Steer 进入当前轮；Queue 等待后续并可编辑或删除 |
| 查看命令或文件变化 | 展开实际输出、退出码与差异；处理真实批准 |
| 打开生成的网页 | 宿主校验文件范围后交给 Safari，HTML 与产品凭据隔离 |
| 回到原讨论继续迭代 | 自动回传对应执行结果，保留未发送草稿 |

## 连接方式

ChatGPT 一侧使用官网网页，Codex 一侧使用官方 App Server 客户端协议。TWOS 实现适合单窗口的消息、输入、工具和成果界面，不能宣称官方 macOS App 的整个 GUI 已被直接嵌入。

当前需要已安装并登录的本机 Codex。模型能力、推理选项、额度和服务错误来自实际供应商；没有额外的 TWOS 调用次数上限。

## 用量与工作进展

右栏 **额度与用量 / Usage & Limits** 通过当前 Codex 连接读取服务返回的窗口、重置时间与用量，并单列线程 Token 及本地观测次数。未知字段明确说明，不把 Token、Credits 和费用混为一谈。

**运行活动 / Run Activity** 显示真实开始、已观测时间、工具状态、计划步骤及结果回传。轻量 ETA 使用已观测计划步骤耗时，证据不足时给出原因；不是固定倒计时或官方承诺。等待输入和离线分别显示，刷新状态不会重跑模型。

**语言 / Language** 保存 TWOS 的中英文偏好，不翻译用户内容或改动左侧官网设置。首次任务可以使用已有空目录、在原生选择器新建目录，或明确授权保留内容的已有项目；接续任务复用有效绑定。

## 数据与执行边界

任务目录需要明确确认。新目录创建新绑定，不静默迁移活动任务。模型文字不是授权，打开文件不是功能验收，执行通道结束不是业务成功。刷新与重启保留草稿和交付记录，未知送达先核对再行动。

成果区可以打开网页、查看文件、在 Finder 定位，并通过 **另存为…** 保存单个文件副本。保存位置由 macOS 原生窗口选择，原任务文件保留；无需重新执行任务。

已有账号、邮箱及原项目入口保持；旧项目的操作流程不作为新工作台的前置步骤。其他模型、私人业务数据和公开发布的权限不会自动扩大。
