## 2. 页面A：完整 TWOS 邮箱注册/登录

参考 ChatGPT 熟悉的简洁交互，不复制 OpenAI 品牌，不冒充 OpenAI 登录。TWOS 自有账号与连接 ChatGPT/Codex 的授权是两个独立步骤。

入口：注册账号 / 登录，默认 English，顶部语言选择持续可见。本轮邮箱主线，不强塞 Google/Apple/手机/SSO/组织角色设置。

新注册：邮箱 → 设置密码 → 明确发送验证邮件 → 输入六位验证码 → 邮箱验证成功 → 进入空白首页。
已有用户：邮箱 → 密码 → 登录 → 恢复本账号原状态。未验证邮箱须进入对应验证；已有效会话不每次重启强制验证。
支持：重发验证码、修改邮箱、错误/过期/尝试过多、发信失败/限流、返回上一步、密码显示/隐藏、退出登录、会话过期重登。
找回：邮箱 → 与注册用途不同的重置验证码 → 有时限的一次性重置授权 → 新密码及确认 → 重新登录。重置后旧密码及应撤销会话不继续有效。

### 身份与数据实现原则
- 优先使用已有、受支持身份组件及邮件服务；没有就以成熟组件实现最薄必要层，不新建会员/企业/计费平台。
- “邮箱已验证”必须由可信服务端依据对应账号、邮箱、用途和有效挑战记录判定；不能由客户端字段、公开查询参数或固定演示码设置。
- 本机应用的邮件发送秘密不能共享内嵌在公开 DMG 中，也不能用前端持有服务级凭据。可选已有可信身份/邮件网关或管理员合法本机配置，按现有条件选最小方案；实际连通前不得编造平台已配置。
- 发件服务只接收必要邮箱和验证模板，不上传项目资料、模型凭据或工作内容；邮箱服务/域名/套餐的新购需要Owner批准，不能隐式新增费用。
- 实际邮箱验证应在已授权测试邮箱上收取真实邮件，输入真实验证码；SMTP接受请求不等于邮件到达，更不等于邮箱验证通过。
- 验证码不可预测、限时、一次性；重发使旧挑战失效，限制重发频率与尝试次数；注册验证不能换作重置密码或模型授权。
- 避免账号枚举、重放、跨会话/跨账号挑战、暴力尝试和无边界邮件发送；使用成熟密码哈希/KDF和安全会话机制，不复制原型的内存演示。
- 密码/验证码/token不写明文日志、不放浏览器localStorage或Git/ZIP；错误提示可操作但不泄露秘密。
- 兼容现有已接受的本地账号；新增邮箱绑定须原账号登录及对邮箱实际验证后明确确认。不能凭同名/同邮箱自动合并账号或迁移资料。
- 邮箱登录不意味着项目已云同步；未经实现/授权不得声称跨设备资料同步。
- 普通用户不应配置SMTP；维护者依赖尚未闭合时给一个具体最小动作，不把技术设置塞进新用户主线。

完整邮件依赖或真实验证缺证据时：EMAIL_AUTH_REAL_GATE=BLOCKED。工程替身/原型“演示收件箱”只能是局部测试，不能进入产品发行模式。
